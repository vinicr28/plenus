  6. ROTAS DE API
================================================================================

─── PÚBLICAS ───

POST /api/send-email
  → Envia email via Resend + salva lead + push ntfy
  → Usado por: contact, pos-venda, trabalhe-conosco
  → Body: { formType: string, data: { nome, telefone, ... } }

POST /api/save-lead
  → Salva lead direto no banco + push ntfy (sem email)
  → Usado por: financiamento
  → Body: { formType: string, data: { nome, telefone, email, ... } }

GET  /api/projects          → Projetos publicados (published=true)
GET  /api/reviews           → Avaliações aprovadas (approved=true)
GET  /api/hero-stats        → Estatísticas do hero
GET  /api/financing/settings → Taxa de juros atual
POST /api/track-event       → Registrar evento de projeto (view/click)

─── ADMIN (requerem autenticação) ───

GET/POST     /api/admin/projects       → Listar / criar projetos
GET/PUT/DEL  /api/admin/projects/[id]  → Detalhe / editar / deletar projeto
GET/POST     /api/admin/reviews        → Listar / criar avaliações
PUT/DEL      /api/admin/reviews/[id]   → Aprovar / deletar avaliação
GET          /api/admin/leads          → Listar leads
PUT/DEL      /api/admin/leads/[id]     → Atualizar status / deletar lead
GET/PUT      /api/admin/financing      → Ver / atualizar taxa de juros
GET/PUT      /api/admin/hero-stats     → Ver / atualizar stats
POST         /api/admin/upload         → Upload de imagem (Supabase Storage)
GET/POST/DEL /api/admin/users          → Listar / criar / remover admins

  8. FORMULÁRIOS (FLUXO COMPLETO)
================================================================================

─── CONTATO (Contact.tsx) ───
  Campos: nome*, telefone*, tipoProjeto, mensagem
  API:    POST /api/send-email { formType: "contact", data: {...} }
  Fluxo:
    1. Usuário preenche → submit
    2. API envia email (Resend) para Alison e Danilo
    3. API salva lead na tabela "leads" (form_type="contact")
    4. API envia push notification (ntfy.sh)
    5. Mostra mensagem de sucesso

─── PÓS-VENDA (PosVenda.tsx) ───
  Campos: nome*, telefone*, endereco*, mensagem
  API:    POST /api/send-email { formType: "pos-venda", data: {...} }
  Fluxo:  Mesmo do contato

─── TRABALHE CONOSCO (TrabalheConosco.tsx) ───
  Campos: nome*, email*, telefone*, areaInteresse*, sobreVoce*
  API:    POST /api/send-email { formType: "trabalhe-conosco", data: {...} }
  Fluxo:  Mesmo do contato (abre em modal)

─── FINANCIAMENTO (FinanciamentoClient.tsx) ───
  Campos: nome*, telefone*, email*, mensagem
  API:    POST /api/save-lead { formType: "financiamento", data: {...} }
  Fluxo:
    1. Usuário preenche → submit
    2. API salva lead na tabela "leads" (form_type="financiamento")
    3. API envia push notification (ntfy.sh)
    4. NÃO envia email

  9. BANCO DE DADOS (SUPABASE)
================================================================================

Projeto: ktpmwrjlargiyszzleve
URL:     https://ktpmwrjlargiyszzleve.supabase.co
Painel:  https://supabase.com/dashboard/project/ktpmwrjlargiyszzleve

─── TABELAS ───

projects
  - id (uuid, PK)
  - title, location, area, category
  - image_url (imagem principal)
  - images (text[] — array de URLs)
  - video_url
  - description
  - published (boolean — só publicados aparecem no site)
  - created_at, updated_at

reviews
  - id (uuid, PK)
  - name, email, rating (1-5), comment, location
  - approved (boolean — só aprovados aparecem no site)
  - created_at

leads
  - id (uuid, PK)
  - form_type ('contact' | 'pos-venda' | 'trabalhe-conosco' | 'financiamento')
  - status ('novo' | 'em_negociacao' | 'fechado')

  - tipo_projeto, mensagem, assunto, descricao
  - area_interesse, sobre_voce
  - cpf, endereco, data_nascimento, observacao
  - notes (notas internas do admin)
  - created_at, updated_at

project_events
  - id (uuid, PK)
  - project_id (FK → projects)
  - event_type ('modal_open' | 'cta_click')
  - created_at

financing_settings
  - id (uuid, PK)
  - key (text, ex: 'interest_rate')
  - value (jsonb, ex: { annual_rate: 12.5, description: "..." })
  - updated_at

hero_stats
  - id (uuid, PK)
  - position (int, 1-4)
  - value (text, ex: "500+")
  - label (text, ex: "Casas Entregues")
  - prefix (text, opcional, ex: "R$")
  - updated_at

─── STORAGE ───

Bucket: project-images (público)
  - Usado para imagens de projetos
  - Upload via /api/admin/upload
  - URL formato: {SUPABASE_URL}/storage/v1/object/public/project-images/{filename}

─── RLS (Row Level Security) ───

  - Público pode LER projects (published=true) e reviews (approved=true)
  - Público pode INSERIR leads e reviews
  - Admin (autenticado) tem acesso total a todas as tabelas
  - Service role key bypassa RLS (usado no server)

─── SCHEMA SQL ───

O arquivo supabase-production.sql na raiz do projeto contém o schema
completo para recriar o banco do zero se necessário.


================================================================================
  10. AUTENTICAÇÃO (LOGIN ADMIN)
================================================================================

Sistema: Supabase Auth (email + senha)

Fluxo:
  1. Usuário acessa /admin/login
  2. Digita email e senha
  3. Chama supabase.auth.signInWithPassword()
  4. Sucesso → redireciona para /admin/dashboard
  5. Erro → mostra "Email ou senha incorretos"

Sessão:
  - Armazenada em cookies (SSR) e localStorage (client)
  - Gerenciada pelo @supabase/ssr

Criar novo admin:
  - Via /admin/settings → form "Adicionar novo administrador"
  - Ou via Supabase Dashboard → Authentication → Users → Add user

Logout:
  - Botão "Sair" na sidebar
  - Chama supabase.auth.signOut()
  - Redireciona para /admin/login

API admin:
  - Todas as rotas /api/admin/* verificam autenticação
  - createClient() (com cookies) → getUser() → se não autenticado, retorna 401
  - Operações admin (listar/criar/deletar users) usam createServiceClient()
    que usa a service role key (sb_secret_...)

================================================================================
  12. NOTIFICAÇÕES PUSH (ntfy.sh)
================================================================================

ntfy.sh é um serviço gratuito de push notifications via HTTP.
Não requer conta — qualquer pessoa com o nome do tópico pode receber.

─── COMO FUNCIONA ───

  1. Quando um lead é capturado, a API faz POST para:
     https://ntfy.sh/plenus_obras

  2. O POST envia:
     - Título: "Novo Lead - {tipo do formulário}"
     - Corpo: nome + telefone + horário
     - Prioridade: high
     - Tag: incoming_envelope (emoji de carta)

  3. Qualquer dispositivo inscrito no tópico recebe a notificação.

Código: src/lib/notify.ts

─── COMO CONFIGURAR UM CELULAR ───

  Android:
    1. Instalar app "ntfy" da Play Store
       (https://play.google.com/store/apps/details?id=io.heckel.ntfy)
    2. Abrir o app
    3. Tocar no "+" (adicionar assinatura)
    4. Em "Topic name", digitar: plenus_obras
    5. Manter o servidor padrão (ntfy.sh)
    6. Tocar em "Subscribe"
    7. Pronto! Vai receber notificação a cada novo lead.

  iPhone:
    1. Instalar app "ntfy" da App Store
       (https://apps.apple.com/app/ntfy/id1625396347)
    2. Abrir o app
    3. Tocar no "+" para adicionar
    4. Em "Topic", digitar: plenus_obras
    5. Server: ntfy.sh (padrão)
    6. Tocar em "Subscribe"
    7. IMPORTANTE: Permitir notificações quando o iOS pedir
    8. Pronto!

  Desktop (browser):
    1. Acessar https://ntfy.sh/plenus_obras
    2. Clicar em "Subscribe" / permitir notificações
    3. Vai receber push no browser

─── TESTAR ───

  Para testar se está funcionando, rodar no terminal:

    curl -d "Teste de notificação" ntfy.sh/plenus_obras

  Ou acessar https://ntfy.sh/plenus_obras e enviar uma mensagem.

─── TROCAR O TÓPICO ───

  Se precisar trocar (ex: por segurança), basta:
    1. Mudar NTFY_TOPIC no .env.local
    2. Reinscrever os celulares no novo tópico
    3. Deploy

─── SEGURANÇA ───

  O tópico "plenus_obras" é público. Qualquer pessoa que souber o nome
  pode se inscrever. Se for um problema, considere:
    - Usar um nome aleatório difícil de adivinhar
    - Ou usar ntfy.sh com autenticação (plano pago)

================================================================================
  16. TROUBLESHOOTING / ERROS COMUNS
================================================================================

─── Scroll travado no site público ───
  Causa: Componentes que setam body.style.overflow = "hidden" ao abrir modal
         e não restauram corretamente ao fechar.
  Solução: Todos os modais devem usar o hook useScrollLock (src/lib/useScrollLock.ts).
           Ele usa um counter para gerenciar múltiplos modais simultâneos.
  Componentes que usam: Process.tsx, ProjectModal.tsx, TrabalheConosco.tsx
  CSS importante: globals.css usa overflow-x: clip no body (não hidden!).
                  "clip" esconde overflow horizontal sem criar scroll container.

─── Admin scroll não funciona ───
  O layout admin (src/app/admin/layout.tsx) usa:
    - Wrapper: fixed inset-0 (posição fixa cobrindo toda a viewport)
    - Sidebar: h-full shrink-0
    - Main: flex-1 overflow-y-auto
  Se mudar para h-screen ou min-h-screen, o scroll pode quebrar porque
  html/body podem criar scroll containers conflitantes.

─── API /api/admin/users retorna 500 ───
  Causa: SUPABASE_SERVICE_ROLE_KEY incorreta.
  A service role key NÃO é a mesma que a anon key.
  - Anon key: começa com "eyJ..." ou "sb_publishable_..."
  - Service role key: começa com "sb_secret_..."
  Encontrar no painel: Supabase Dashboard → Settings → API Keys

─── Emails não chegam ───
  1. Verificar RESEND_API_KEY no .env.local
  2. Verificar EMAIL_TO (emails separados por vírgula)
  3. Verificar logs no Resend Dashboard (resend.dev)
  4. O remetente é onboarding@resend.dev — pode cair no spam

─── Notificações push não chegam ───
  1. Verificar NTFY_TOPIC no .env.local
  2. Testar manualmente: curl -d "teste" ntfy.sh/plenus_obras
  3. Verificar se o app ntfy está instalado e inscrito no tópico correto
  4. No iPhone, verificar se notificações estão permitidas

─── Imagens de projeto não carregam ───
  1. Verificar se o bucket "project-images" existe no Supabase Storage
  2. Verificar se o bucket é público
  3. Verificar se a URL da imagem está correta

─── Login admin não funciona ───
  1. Verificar NEXT_PUBLIC_SUPABASE_URL e NEXT_PUBLIC_SUPABASE_ANON_KEY
  2. Verificar se o usuário existe no Supabase Auth
  3. Criar usuário via /admin/settings ou via Supabase Dashboard

─── Build falha ───
  1. Limpar cache: rm -rf .next/cache
  2. Reinstalar deps: rm -rf node_modules && npm install
  3. Verificar erros de TypeScript: npm run lint

─── Financiamento mostra taxa errada ───
  A taxa é configurável em /admin/financing.
  Tabela: financing_settings, key: "interest_rate"
  Valor: { annual_rate: X.XX }
